Abstract
Disaggregated large language model serving separates prompt processing from autoregressive decoding, but
request heterogeneity continues to influence queueing delay and service-level objective (SLO) attainment. This
study presents SmartDistServe, a reproducible discrete-event simulation prototype comparing phase-local
first-come-first-served (FCFS), estimated shortest-job-first (SJF), earliest-deadline-first (EDF), and a heuristic
combining normalized deadline slack, estimated request duration, and aging. Evaluation comprises 440 policy
runs on 110 stored synthetic trace instances using five seeds. Metrics include time to first token, time per output
token, joint SLO attainment, cohort goodput per GPU, tail waiting time, and group-outcome fairness. Across 16
main conditions, the heuristic exceeds FCFS in mean attainment in four conditions, falls below it in four, and ties
in eight. Under mixed overload at six requests per second, estimated SJF achieves 55.30% mean attainment
compared with 13.45% for the heuristic, while its mean run-level P95 waiting time increases from 28.10 to 61.71
seconds. The results identify performance tradeoffs rather than universal policy superiority. All workloads are
synthetic and service coefficients are uncalibrated; improvement over physical serving systems is not established.
Keywords: LLM serving; disaggregation; discrete-event simulation; deadline scheduling; SLO attainment; fairness.
1. Introduction
DistServe (Zhong et al., OSDI 2024) [1] separates prefill and decoding onto different GPUs, uses FCFS runtime
ordering with queue/load-based routing, and optimizes placement and resource allocation. Its runtime section
discusses convoy effects and complementary scheduling changes. SmartDistServe adopts separate phase
resources, first-token generation during prefill, and a simplified shortest-queue/least-occupancy FCFS reference.
It does not implement DistServe's placement optimizer, tensor/pipeline parallelism, CUDA kernels, KV memory
manager, or engine. Comparing policies here does not measure improvement over the published DistServe
system.
2. Related Work and Contribution
Priority, short-job scheduling, deadline ordering, and aging are established techniques. Prior LLM-serving studies
address output-length prediction, request prioritization, and differentiated service objectives:
- Qiu et al., Efficient Interactive LLM Serving with Proxy Model-based Sequence Length Prediction (2024) [2] uses
 a proxy predictor for speculative SJF.
- Fu et al., Efficient LLM Scheduling by Learning to Rank (2024) [3] predicts relative output-length ranks for
 scheduling.
- Sun et al., Llumnix (OSDI 2024) [4] supports runtime rescheduling, differentiated priorities, and SLOs across
 instances.
- Huang et al., SLO-Aware Scheduling for Large Language Model Inferences (2025) [5] considers request SLOs,
 input lengths, and possible output lengths when choosing priority order.
- Wu et al., FastServe (NSDI 2026) [6] uses token-level preemption and a skip-join feedback scheduler. This
 prototype does not reproduce its preemption or offload machinery.
The contribution is a reproducible experimental artifact combining these ideas with explicit disaggregated queues
and fairness diagnostics. Its particular score is a study heuristic, with no proof of optimality or literature-backed

3. System Model and Scheduling Policies
Two prefill GPUs and one decode GPU are provisioned in the reference configuration. A request routes at arrival
to the prefill GPU with the smallest number of queued plus running requests; ties use GPU ID. Each GPU
processes one prefill at a time, nonpreemptively. Prefill completion emits token 1. The modeled KV transfer then
completes independently, with no shared-link contention. A request routes to the decode GPU with the fewest
active plus queued requests. Decode admits requests between iterations into at most 16 active slots and
generates one token per active request per iteration. An admitted request keeps its slot until completion; priority
only changes admission. At coincident timestamps, completions release resources before transfers and arrivals
route, and all events are processed before dispatch. All policies share routing, batching, hardware, SLOs, and
realized traces. They do not drop requests or cancel requests with expired deadlines.
For prompt length L, current batch B, and maximum active context C:
prefill(L) = 0.005 + L/8000 + 0.01*(L/4096)^2          seconds
transfer(L) = 0.002 + L*131072/25000000000             seconds
decode_step(B,C) = 0.012 + 0.0006*(B-1) + 0.00000025*C seconds
These functions are deliberately simple synthetic cost assumptions. GPU counts mean one abstract worker per
GPU; model parallelism and model-fit feasibility are not represented.
FCFS orders by phase enqueue time. Estimated SJF orders by estimated service for the phase (prefill duration or
predicted remaining decode duration). EDF orders by the phase deadline. Prefill deadline is arrival plus TTFT SLO.
Decode uses a proxy completion deadline first_token + max(1, estimated_output_tokens-1)*TPOT_SLO; exact
output length is unknown to the scheduler, so this is not an oracle EDF or a guarantee of TPOT success.
Let e be phase enqueue time, d the phase deadline, s the estimated remaining phase service, D the estimated
duration (prefill + transfer + decode before prefill, remaining decode before decode admission), and b the phase
SLO budget. At time t, Smart selects the smallest score:
slack = d - t - s
score = (slack + 0.1*D - 0.2*(t-e)) / b
Each score normalizes by its request's budget: TTFT SLO for prefill, estimated post-first-token count times TPOT
SLO for decode. Negative slack remains eligible and can get high priority. Before scoring, any request waiting at
least five seconds is promoted; the oldest eligible request wins. Ties use enqueue time then request ID. This aging
rule gives eventual admission with bounded service and a finite number of older requests, but it provides no fixed
waiting-time bound under overload and cannot interrupt long running prefill or decode requests. SJF and EDF do
not receive aging; the ablation removes it from Smart to expose that difference.

low/high rates are normalized to the configured average over a full period. The main grid uses four rates per
profile and mixed workload. Mixed request probabilities are 50% chat, 25% code, and 25% long-context. Each run
accepts arrivals for 90 simulated seconds. Only arrivals in [15,90) enter the measured cohort; the first 15 seconds
warm up queues, and every arrival is fully drained afterward. The measurement is transient and finite, especially at
overloaded rates. Five seeds are shared across all policies. Ablations at mixed rate 3 req/s remove aging, remove
the duration term, use a profile prior without extra noise, increase noise, enable bursts, and slow KV transfer. No
parameters were selected to force a desired outcome.
5. Evaluation Metrics
- TTFT = first-token timestamp minus arrival, including prefill queue wait.

- TPOT = (completion-first_token)/(output_tokens-1), including transfer and decode admission wait.
 One-token requests have undefined TPOT, omitted from TPOT averages and treated as satisfying the TPOT
constraint. Max observed token gap is retained because average TPOT can hide a long initial decode stall.
- Joint SLO attainment = fraction of cohort requests satisfying both TTFT and average TPOT limits, with a
 1e-12-second numerical boundary tolerance.
- Cohort per-GPU goodput = joint successes divided by (90-15) seconds and all provisioned GPUs. It counts
 successes for cohort arrivals even if they finish during drain. It is neither token throughput nor steady-state
maximum sustainable rate.
- Waiting = prefill queue wait plus decode admission wait. Transfer and active service are excluded; P95 uses
 linear interpolation.
- Fairness = Jain index over per-profile and fixed prompt-size-bin joint SLO attainment rates. Prompt bins are
 <=512, 513..2048, and >2048; empty bins are omitted. All-zero group attainment maps to zero. Single
populated-group Jain equals one and cannot establish fairness; differing per-group SLOs also limit
interpretation. Per-group counts, waiting tails, max wait, and P95 size-normalized slowdown supplement the
index.
- Slowdown uses end-to-end latency divided by this model's isolated request service; it is a diagnostic, not a
 tenant service-share guarantee.

6.3. Performance Tradeoffs
At mixed rate 3 req/s, mean joint SLO attainment is 89.58% (FCFS), 90.41% (Smart), 92.50% (SJF), and 92.33%
(EDF). Mean run P95 queue wait is 1.840 s (FCFS), 1.813 s (Smart), 1.693 s (SJF), and 1.597 s (EDF). Aggregate
attainment and tail waiting therefore need to be assessed together; a higher successful-request rate alone does
not establish better fairness.
At mixed rate 6 req/s, mean joint SLO attainment is 9.55% (FCFS), 13.45% (Smart), 55.30% (SJF), and 25.64% (EDF).
Mean run P95 queue wait is 28.709 s (FCFS), 28.096 s (Smart), 61.711 s (SJF), and 30.222 s (EDF). Aggregate
attainment and tail waiting therefore need to be assessed together; a higher successful-request rate alone does
not establish better fairness.
Removing both aging mechanisms changes mean mixed-rate-3 Smart attainment from 90.41% to 90.14% (-0.264
percentage points). This is one operating point, so it does not establish a general effect or a statistically reliable
component benefit.
Removing the duration term changes mean mixed-rate-3 Smart attainment from 90.41% to 91.52% (+1.111
percentage points). This is one operating point, so it does not establish a general effect or a statistically reliable
component benefit.

7. Limitations and Threats to Validity
The numerical results are conditional on the stated synthetic distributions, arbitrary cost model, SLOs, GPU
allocation, batch limit, and heuristic weights. They do not estimate physical GPU throughput, DistServe speedup,
dataset fidelity, energy, cost, or production viability. There is no KV capacity limit, memory fragmentation, swap,
preemption, prefix reuse, speculative decoding, transfer contention, pipeline/tensor communication, admission
rejection, model quality, tokenization, hardware variance, or scheduler computation overhead. Active decode and
prefill work cannot be displaced. Shared local queues can cause routing imbalance; queue length is not remaining
work. CPU runtime is not converted to simulated scheduling overhead.
The workload has no tenants beyond application groups, no correlated input/output lengths, and no learned
estimates. Five seeds yield broad uncertainty for some cases. No confidence interval represents cost-model
uncertainty. The suite is a fixed finite grid; capacity diagnostics do not locate the exact saturation boundary, and
complete draining is not a substitute for long steady-state runs. Fairness indices of SLO outcomes differ from
resource fairness and can rise even when all groups perform poorly. The reference reports absolute SLO rates and
group details so this cannot be hidden by a single index.

Results establish only how the implemented policies behave within this simulator. Scheduling can change which
requests meet their SLOs and can trade aggregate success against tail wait or group outcomes. The tables include
regressions and ties. A claim that Smart always outperforms FCFS, SJF, or EDF is unsupported. The next research
steps are measured service profiling, licensed trace acquisition with tokenizer provenance, learned or rank-based
estimate evaluation, strong SLO/fair scheduling baselines, explicit memory and link models, load-duration
sensitivity, and eventual GPU validation.
8. Reproducibility and Artifact Validation
The README supplies commands for tests, experiments, plots, independent audit, and exact metric replay.
manifest.json records configuration, seeds, trace hashes, numeric output hashes, source hashes, Python version,
and platform. requests.csv.gz contains per-request outcomes; traces.jsonl.gz contains complete input traces.
summary.csv and paired_contrasts.json retain seed uncertainty. Graphs are generated only from measured JSON.
research/REVIEW.md records the final code and result review, discovered issues, fixes, and checks actually
executed. Passing these checks supports internal consistency, not real-world validity.
The final simulator passed 38 automated tests. Independent recomputation from serialized timelines completed
1,505,479 checks with 0 failures across 149,400 policy-specific request outcomes. Replay reproduced exact
metrics for all 440 runs. The 110 stored trace instances include deliberately reused realizations for paired
component ablations; policy outcomes are not treated as independent statistical samples.
Code review identified and corrected configuration-option precedence and coincident-event routing issues.
Completion events now release resources before simultaneous arrivals and transfers are routed. The reference
suite was rerun after this correction and its numerical output hashes remained unchanged. Validation establishes
internal consistency and determinism rather than physical-model accuracy.
9. Conclusion
SmartDistServe provides a reproducible simulation artifact for evaluating phase-local scheduling in disaggregated
LLM serving. Within the tested synthetic workload grid, the slack, duration, and aging heuristic improves mean
joint SLO attainment over FCFS in four conditions, reduces it in four, and ties in eight. Estimated SJF can achieve
substantially higher attainment under overload while increasing tail waiting. These findings support evaluation of
multiple performance and fairness measures rather than a claim of universal policy superiority. The principal
contribution is the experimental integration and its inspectable measured tradeoffs; algorithmic novelty and
improvement over the physical DistServe system are not established. Empirical traces, calibrated service models,
stronger baselines, and physical GPU evaluation remain necessary for external validation.

Appendix A. Reproduction Procedure
The following commands execute from the repository root. Simulation, tests, auditing, and reporting require
Python 3.11 or later and the standard library. Plot generation requires the pinned dependencies in
requirements-plots.txt. The reference manifest records the precise Python environment and source hashes.
python -m unittest discover -s tests -v

python -m smartdistserve report --results results/reference
python scripts/audit_results.py --results results/reference
python scripts/replay_results.py --results results/reference
python scripts/plot_results.py --results results/reference
The saved manifest contains all workload definitions, seeds, hardware and scheduler settings, source hashes, trace
hashes, and output hashes. Complete inputs are retained in traces.jsonl.gz; policy-specific timestamps,
measured-cohort flags, and success outcomes are retained in requests.csv.gz. Seed-level metrics, group statistics,
aggregate uncertainty, and paired contrasts are retained separately. All requests are drained; failed or late
requests are not censored.
